Where the audio lives

The reference clips have to come from somewhere, and the page must say clearly where it looked when it finds nothing. The design is one swappable source, so changing where the audio lives never means changing the player.

Three places, tried in this order

  1. Your own files. Clips you picked on this device.
  2. A copy on the device, called offline: saved earlier, so the verse plays with no network.
  3. The cloud: the same website the app is served from.

If none of them has the verse, the page says "No audio for verse N", names what it tried, and disables the play button. It never fails silently.

Why the cloud is the app's own website

A day's clips are 14 files and about 3 MB. On the app's own GitHub Pages site they cost nothing and the page can read and analyse them, because they come from the same place. Files attached to a GitHub release cannot do this job: the page is not allowed to read them, and an unpublished release answers "not found" to the public (report 2, GitHub limits).

Offline, and the iPhone catch

The design is a download button that saves the clips on the device after checking each one. On an iPhone, Safari deletes a site's stored data after 7 days without a visit unless the app is on the Home Screen (WebKit), so the page should say "Add to Home Screen to keep offline audio". On this test site "offline" is only a folder beside the page; the button is described, not built.

Your own files, and the format

A file picker works everywhere, an iPhone included. Files are matched to verses by the number in the name: verse-07.mp3 is verse 7. The format is MP3, mono, constant bitrate, which every major browser plays (MDN).

For the technically curious

GitHub allows 1 GB per Pages site and a soft 100 GB of downloads a month, about 34,000 full downloads of a 2.9 MB day set (a calculation). Release files send no CORS header; the browser cannot read them for analysis. Cloudflare R2 would be free at this size, but its test address is rate-limited and a real one needs a custom domain (source). Offline storage would use Cache Storage after a SHA-256 check, with the service worker slicing partial responses; the server-side Quran.com API uses the same catalogue plus relative key pattern (source). Folder pickers exist only in Chrome and Edge 105 and later (caniuse). At 128 kilobits per second a 12 second clip is about 192 KB; constant bitrate keeps jumps to a syllable exact and variable bitrate may drift, and 64 kilobits would halve the set but needs a listening check (both hypotheses). Whether the iOS 7-day rule still holds in iOS 26 was not checked (hypothesis). Source for all: report 2.
